# 重构架构与兼容边界

用户已授权按前轮讨论实施独立工程重构。源工程只读；baseline保存原始四个业务文件与MDK配置。

采用裸机协作状态机：app负责生产/激活/常规策略；components负责采集、定位及网络流程；core保存纯类型和UTC算法；services负责AT事务、HTTP、文本协议、缓存、参数与存储；platform独占寄存器、IRQ、时钟和引脚；vendor仅保留原厂库。中断仅收字节、计时及按键事件，业务不在IRQ运行。无RTOS、QP和动态分配。

保持：HC32L130F8UA、RCH22.12MHz、UART0 PA9/10 115200、PA4/PB4模块控制、PB6/7 I2C0、PA2/6 ADC、PA5采样使能、PA7 LED、PB11按键、XTL RTC。沿用服务器URL、字段及Flash 0xEE00的SN/+30/+40格式。64KiB Flash/8KiB RAM。板卡版本、模块型号、温度转换和时区仍未知。

有意修复：首次HTTP失败不永久停机；有界ADC/I2C；邻区最多3项；准确正文长度；配置整组验证后提交；每条完整采集记录缓存；自检不改正常调度；真实时间调度；全局状态封装；按键与UART临界区；Flash区域显式保留。

自检：三次短按启动检查，分别取得两种定位，服务器status=1才提交自检标记，之后等待三次短按激活。失败回到可重试状态，不自动激活。空白设备先初始化UART接收六位SN。正常：首次上报，随后RTC约10分钟采样，按运动/静止配置决定上报；按键只提示，不提前推进名义周期。

网络首试保留Tele2→按MCC进入俄罗斯双运营商轮询；Ping失败只表示当前探测失败，不声称运营商封锁。命令/操作期限来自旧显式延时和工程集中默认值，原迭代计数超时不能精确换算，新的毫秒预算需上板核对。HTTP上传接受与配置更新分离：HTTP200后还需收到完整响应正文；配置缺失不重复排队已确认记录。

Flash不自动擦除已有SN；六位SN仅写空白记录，先写低3字节，最后第4字节提交，兼容旧启动判据。标记采用1到0追加，读取时只接受精确标记值。禁止运行时重写SN；这避免擦除破坏已有激活数据。未知扇区几何不作为自动擦除依据。

接口：AT异步事务单所有者，同步借用发送文本直到启动返回，响应由AT静态对象保存到下一次启动；禁止重入。AT超时取消后有静默排空窗，仍无法给无事务标识的模块URC提供完美关联，列入实板故障注入。采样结果按值复制。HTTP只借用记录到操作完成，不改变调用者记录。

状态机采用分解后的enum+switch，各状态单步推进，有完成/失败/超时；共享故障处理集中到应用出口，无复杂层级框架。I2C/ADC是短时有界轮询例外，ADC稳定110ms加转换轮询预算100ms，I2C单事务20ms，影响前台最大延迟；网络/定位/HTTP等待完全非阻塞。

资源初预算：UART RX512字节、AT响应768字节、HTTP正文512字节、20条完整记录约1.6KiB、栈2KiB/堆0；最终以map为准。运动方差使用在线算法，不占600字节采样数组。TIM0按1000计数/PCLK256产生约11.573ms节拍，余数累计为毫秒；深睡停TIM0并以RTC差值补偿，墙上时间同步不用于活动通信超时。
